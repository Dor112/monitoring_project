# Мониторинг серверной телеметрии

Прототип для НИРС. Prometheus опрашивает node_exporter на VPS, Python-сервис рассчитывает аномальность, а устанавливаемый app-плагин Grafana показывает результаты через прокси Grafana. Анализ и реагирование идут в фоне, даже если страница закрыта.

## Запуск на Linux VPS

Скопируйте папку проекта на VPS с Docker Engine и Docker Compose v2. Команды ниже выполняются в папке проекта.

1. Создайте файл настроек и задайте уникальный пароль Grafana.

   ```bash
   umask 077
   cp .env.example .env
   chmod 600 .env
   nano .env
   ```

2. Загрузите файлы одного узла SMD из [репозитория авторов OmniAnomaly](https://github.com/NetManAIOps/OmniAnomaly/tree/master/ServerMachineDataset). Номер узла должен совпадать с `SMD_MACHINE` в `.env`.

   ```bash
   machine=machine-1-1
   for group in train test test_label; do
     mkdir -p "data/$group"
     curl --fail --location --show-error \
       "https://raw.githubusercontent.com/NetManAIOps/OmniAnomaly/master/ServerMachineDataset/$group/$machine.txt" \
       -o "data/$group/$machine.txt.part" &&
       mv "data/$group/$machine.txt.part" "data/$group/$machine.txt" || exit 1
   done
   chmod a+rx data data/train data/test data/test_label
   chmod a+r data/{train,test,test_label}/"$machine.txt"
   ```

3. Запустите стенд.

   ```bash
   docker compose up -d --build
   docker compose logs -f monitor grafana
   ```

4. На своём компьютере откройте SSH-туннель, подставив пользователя и адрес VPS.

   ```bash
   ssh -N -L 3000:127.0.0.1:3000 user@VPS
   ```

   Откройте [страницу плагина](http://localhost:3000/a/nirs-servermonitor-app) и войдите под именем `admin` с паролем из `.env`. Docker Compose разрешает загрузку локального неподписанного плагина. Grafana и остальные HTTP-компоненты слушают loopback на VPS.

## Два режима

- **Сервер.** Каждую минуту анализируются загрузка CPU, iowait, использование RAM, дисковые IOPS и входящий/исходящий сетевой трафик. На пустом Prometheus до первого обучения нужно накопить 240 последовательных минут телеметрии. Запускайте стенд в период штатной работы. Модель переобучается при запуске контейнера на доступной непрерывной истории, максимум за 12 часов.
- **SMD.** Обучение и калибровка выполняются на последовательных частях `train`. Разметка `test_label` используется для сравнения с прогнозом на `test`. На странице доступны точечные Precision, Recall и F1 для двух моделей и их комбинации, а также среднее время пакетной обработки. Воспроизведение стартует после обучения. Чтобы повторить его, выполните `docker compose restart monitor`. Номера каналов показываются по порядку столбцов SMD.

На вкладке сервера графики всех шести каналов появляются по мере поступления телеметрии, в том числе до обучения. Можно выбрать интервал до 240 минут и посмотреть значение в отдельном отсчёте. В SMD доступны все 38 каналов и последние 240 отсчётов. По завершении записи её последние данные остаются на экране, а живой сбор продолжается.

Isolation Forest использует текущее значение, среднее, дисперсию и первую разность каждого канала за окно. GRU-автоэнкодер восстанавливает окно. Индексы калибруются на отложенном фрагменте штатного режима, усредняются и сглаживаются. Пороги оцениваются через EVT с переходом к эмпирическим квантилям при недостатке данных хвоста. Метки состояния описывают отклонение от обучающей истории. Топ-3 показывает долю ошибки реконструкции для отдельных каналов. Модели SMD и VPS обучаются отдельно.

## Автоматический перезапуск

`ACTION_MODE=smd` разрешает действие при воспроизведении SMD. `ACTION_MODE=live` включает его по живым метрикам. `ACTION_MODE=off` выключает перезапуски. После изменения выполните `docker compose up -d monitor`.

Для короткой демонстрации на `machine-1-1` задайте `SMD_START_INDEX=3700` в `.env`. В локальной проверке с этим узлом условие перезапуска выполнилось на отсчёте 3763. При стандартной скорости этот фрагмент займёт около шести секунд после обучения. Показатели Precision, Recall и F1 по-прежнему рассчитываются по всей тестовой части с доступным окном.

После трёх критических отсчётов подряд монитор останавливает и запускает собственный HTTP-процесс. Он проверяет ответ нового процесса и записывает старый и новый PID в интерфейс и в лог контейнера. Интервал между попытками составляет минимум пять минут. Проверить текущий PID можно на VPS командой `curl -fsS http://127.0.0.1:18081/` при включённом действии.
